# পাইপত্র — Vercel + Turso দিয়ে ডিপ্লয়

এই সংস্করণটি GitHub → Vercel → Turso — এই তিনটি জিনিস দিয়ে সম্পূর্ণ ফ্রিতে লাইভ করার জন্য বানানো। কোনো VPS বা নিজে-ব্যবস্থাপনা করা সার্ভার লাগবে না।

**কেন Turso?** Vercel-এর সার্ভারলেস ফাংশনে কোনো স্থায়ী ফাইল সিস্টেম নেই — প্রতিটি রিকোয়েস্ট একটি আলাদা, ক্ষণস্থায়ী পরিবেশে চলে। তাই সাধারণ SQLite ফাইল কাজ করবে না। Turso একটি হোস্টেড, SQLite-সামঞ্জস্যপূর্ণ ডেটাবেস (libSQL) — একই কোড, শুধু ডেটা থাকে বাইরে, স্থায়ীভাবে।

## ধাপ ১ — Turso ডেটাবেস বানান

```bash
curl -sSfL https://get.tur.so/install.sh | bash
turso auth login
turso db create paipatro
turso db show paipatro --url
turso db tokens create paipatro
```

দুটো মান (URL ও টোকেন) হাতের কাছে রাখুন — এগুলো পরে Vercel-এ এনভায়রনমেন্ট ভেরিয়েবল হিসেবে বসবে।

*Turso CLI ছাড়াও [turso.tech](https://turso.tech)-এর ড্যাশবোর্ড থেকে ফ্রি অ্যাকাউন্ট খুলে একই কাজ ব্রাউজার থেকেই করা যায়।*

## ধাপ ২ — সিক্রেট তৈরি করুন

```bash
# JWT সিক্রেট
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

লেখকের জন্য আলাদা পাসওয়ার্ড হ্যাশ বানানোর দরকার নেই — এখন যে কেউ (লেখক বা পাঠক) সরাসরি সাইট থেকেই "নতুন অ্যাকাউন্ট খুলুন" দিয়ে নিজের ফোন নম্বর ও পাসওয়ার্ড দিয়ে রেজিস্টার করতে পারেন। আপনি (লেখক) যে নম্বর দিয়ে রেজিস্টার করবেন, সেটাই `AUTHOR_PHONE`-এ বসিয়ে দিন — তাহলে সেই অ্যাকাউন্টটাই স্বয়ংক্রিয়ভাবে লেখক-অধিকার পাবে।

## ধাপ ৩ — লোকালি একবার টেস্ট করুন (ঐচ্ছিক কিন্তু সুপারিশকৃত)

```bash
npm install
cp .env.example .env
# .env-এ JWT_SECRET, AUTHOR_PHONE (আপনার নিজের নম্বর), TURSO_DATABASE_URL, TURSO_AUTH_TOKEN বসান
npm run seed     # নমুনা লেখা দিয়ে ডেটাবেস পূরণ করবে (Turso-তে সরাসরি)
npm start        # http://localhost:3000 -এ চেক করুন, তারপর "লগইন" থেকে "নতুন অ্যাকাউন্ট খুলুন" দিয়ে নিজের নম্বর দিয়ে রেজিস্টার করুন
```

TURSO_* ভেরিয়েবল খালি রাখলে একটি লোকাল ফাইলে (`local-dev.db`) চলবে — শুধু কোড টেস্ট করার জন্য ভালো, কিন্তু এতে সংরক্ষিত ডেটা Vercel-এ দেখা যাবে না। লাইভ করার আগে আসল Turso URL/টোকেন দিয়ে একবার `npm run seed` চালিয়ে নিন যাতে প্রকৃত ডেটাবেসেও প্রাথমিক লেখা থাকে।

## ধাপ ৪ — GitHub-এ পুশ করুন

```bash
git init
git add .
git commit -m "পাইপত্র ব্লগ"
git branch -M main
git remote add origin https://github.com/<your-username>/paipatro.git
git push -u origin main
```

(`.env` ফাইলটি `.gitignore`-এ আছে, তাই সিক্রেট পুশ হবে না — এটা ইচ্ছাকৃত ও গুরুত্বপূর্ণ।)

## ধাপ ৫ — Vercel-এ ইমপোর্ট করুন

1. [vercel.com](https://vercel.com)-এ গিয়ে GitHub দিয়ে সাইন-ইন করুন
2. "Add New Project" → আপনার রিপো সিলেক্ট করুন
3. Framework Preset: "Other" (অটো-ডিটেক্ট না হলে)
4. **Environment Variables** সেকশনে যোগ করুন:
   - `JWT_SECRET`
   - `AUTHOR_PHONE`
   - `TURSO_DATABASE_URL`
   - `TURSO_AUTH_TOKEN`
   - `NODE_ENV` = `production`
5. **Deploy** চাপুন

কয়েক সেকেন্ডে সাইট লাইভ হয়ে যাবে — `https://<আপনার-প্রজেক্ট-নাম>.vercel.app` (বা আপনার পছন্দমতো ডোমেইন যোগ করতে পারবেন Vercel-এর Settings থেকে)।

## এরপর প্রতিবার

`main` ব্রাঞ্চে পুশ করলেই Vercel স্বয়ংক্রিয়ভাবে নতুন করে ডিপ্লয় করবে। ডেটাবেস আলাদা (Turso-তে), তাই কোড রিডিপ্লয় করলেও লেখাগুলো মুছে যাবে না।

## কীভাবে কাজ করে (স্থাপত্য)

```
public/          → স্ট্যাটিক ফ্রন্টএন্ড, Vercel সরাসরি CDN থেকে সার্ভ করে
api/index.js     → একটি একক সার্ভারলেস ফাংশন যা পুরো Express অ্যাপ চালায়
vercel.json      → /api/* রিকোয়েস্ট ঐ ফাংশনে পাঠানোর রুটিং নিয়ম
server.js        → Express অ্যাপ (লোকালি "node server.js" দিয়েও চলে, VPS/Render-এও ব্যবহারযোগ্য)
db.js            → Turso/libSQL ক্লায়েন্ট, স্কিমা auto-migration
middleware/rateLimit.js → ডেটাবেস-ভিত্তিক রেট-লিমিটার (সার্ভারলেসে in-memory রেট-লিমিট কাজ করে না,
                          কারণ প্রতিটি ইনভোকেশন আলাদা মেমরিতে চলে — তাই Turso-তেই গণনা রাখা হয়)
```

## নিরাপত্তা — যা অপরিবর্তিত আছে

- পাসওয়ার্ড bcrypt-হ্যাশড, প্লেইন টেক্সটে কোথাও নেই
- httpOnly + sameSite কুকিতে JWT সেশন
- production-এ কুকি শুধু HTTPS-এ কাজ করে (Vercel নিজে থেকেই HTTPS দেয়)
- ব্রুট-ফোর্স প্রতিরোধ — এখন ডেটাবেস-ভিত্তিক, তাই একাধিক সার্ভারলেস ইনস্ট্যান্স জুড়েও কার্যকর
- সব লেখা/সম্পাদনা/মোছার রুট সার্ভার-সাইডে যাচাই হয়

## সীমাবদ্ধতা

- এখন যে কেউ ফোন+পাসওয়ার্ড দিয়ে অ্যাকাউন্ট খুলতে পারে, কিন্তু শুধু `AUTHOR_PHONE`-এ যে নম্বর দেওয়া আছে সেটাই লেখক-অধিকার পায়
- Turso ফ্রি টায়ারে একটি সীমা আছে (মাসিক রো-রিড/রাইট) — ব্যক্তিগত ব্লগের জন্য যথেষ্টের চেয়ে বেশি, কিন্তু ভারী ট্রাফিক হলে turso.tech-এ প্ল্যান দেখে নিন
- পাসওয়ার্ড ভুলে গেলে "রিসেট" ফ্লো নেই — নতুন করে সেই একই ফোন নম্বর দিয়ে অ্যাকাউন্ট বানানো যাবে না (নম্বর ইউনিক), তাই সরাসরি ডেটাবেসে গিয়ে `users` টেবিল থেকে পুরনো রেকর্ড মুছে আবার রেজিস্টার করতে হবে (Turso CLI/ড্যাশবোর্ড থেকে)

## পে-পার-পোস্ট (bKash পেওয়াল)

এখন নির্দিষ্ট লেখায় মূল্য বসিয়ে দেওয়া যায় — পাঠক bKash দিয়ে টাকা দিলে তবেই সম্পূর্ণ লেখাটি পড়তে পারবে। ফ্রি লেখা (মূল্য ০) আগের মতোই সবার জন্য খোলা থাকবে।

### ⚠️ গুরুত্বপূর্ণ সতর্কতা

bKash-এর সার্ভারে সরাসরি সংযোগ করে এই ফিচারটি টেস্ট করা সম্ভব হয়নি (এই কথোপকথনের পরিবেশ থেকে bKash-এর ডোমেইনে নেটওয়ার্ক অ্যাক্সেস নেই)। যা টেস্ট করে নিশ্চিত করা হয়েছে:

- ✅ পোস্টে মূল্য বসানো, তালিকায় মূল্য দেখানো
- ✅ না-কেনা পাঠকের কাছে লেখার মূল অংশ (body) সম্পূর্ণ লুকানো থাকে (সার্ভার থেকেই পাঠানো হয় না)
- ✅ কেনার পর শুধু ওই নির্দিষ্ট পাঠকের জন্যই আনলক হয়, অন্য কারও জন্য না
- ✅ লেখক নিজের পেইড লেখা না কিনেই দেখতে/সম্পাদনা করতে পারেন
- ✅ bKash কনফিগার করা না থাকলে স্পষ্ট এরর মেসেজ দেখায়, সার্ভার ক্র্যাশ করে না

যা টেস্ট করা যায়নি (আপনাকে sandbox-এ নিজে যাচাই করতে হবে):
- ⚠️ bKash-এর token grant/refresh API কল
- ⚠️ Create Payment ও Execute Payment API কল
- ⚠️ callback URL-এ bKash প্রকৃতপক্ষে সঠিক প্যারামিটার পাঠাচ্ছে কিনা

লাইভ করার আগে **sandbox মোডে একটা সম্পূর্ণ পেমেন্ট ফ্লো নিজে চালিয়ে দেখুন**। কোনো ধাপে এরর পেলে `developer.bka.sh/reference`-এর সাথে `middleware/bkash.js` ফাইলটা মিলিয়ে দেখুন — API-র রিকোয়েস্ট/রেসপন্স গঠনে ছোটখাটো পার্থক্য থাকলে ওখানেই ঠিক করতে হবে।

### সেটআপ ধাপ

1. **bKash Merchant/PGW অ্যাকাউন্টের জন্য আবেদন করুন** — bKash-এর বিজনেস টিমের সাথে যোগাযোগ করে মার্চেন্ট অ্যাকাউন্ট খুলুন। অনবোর্ডিং শেষ হলে তারা sandbox ক্রেডেনশিয়াল দেবে (`app_key`, `app_secret`, `username`, `password`)।
2. `.env`-এ (বা Vercel Environment Variables-এ) বসান:
   ```
   BKASH_BASE_URL=https://tokenized.sandbox.bka.sh/v1.2.0-beta
   BKASH_USERNAME=<sandbox username>
   BKASH_PASSWORD=<sandbox password>
   BKASH_APP_KEY=<sandbox app key>
   BKASH_APP_SECRET=<sandbox app secret>
   SITE_URL=https://your-domain.com
   ```
3. sandbox-এ পুরো ফ্লো টেস্ট করুন — সাইটে একটা পেইড লেখা বানান, "bKash দিয়ে পড়ুন" চাপুন, bKash-এর টেস্ট নম্বর/PIN দিয়ে পেমেন্ট সম্পন্ন করুন, দেখুন লেখাটা আনলক হচ্ছে কিনা
4. সব ঠিক থাকলে bKash থেকে production credentials নিয়ে `BKASH_BASE_URL` পাল্টে দিন (production URL bKash-ই জানাবে) এবং env variables আপডেট করুন

### কীভাবে কাজ করে

```
routes/payments.js  → POST /api/payments/bkash/create (পেমেন্ট শুরু), GET /api/payments/bkash/callback (bKash রিডাইরেক্ট)
middleware/bkash.js → bKash-এর token grant/refresh/create/execute API কল, টোকেন DB-তে ক্যাশড
middleware/buyer.js → প্রতিটা ভিজিটরকে একটা বেনামী buyer_id কুকি দেওয়া (কোনো অ্যাকাউন্ট ছাড়াই কে কিনেছে তা মনে রাখতে)
```

purchases টেবিলে `(buyer_id, post_id)` — এই জোড়া UNIQUE, তাই একই পাঠক দ্বিতীয়বার টাকা দিলেও ডুপ্লিকেট এন্ট্রি হবে না। payments টেবিলে প্রতিটা পেমেন্ট চেষ্টার অবস্থা (pending/completed/failed/cancelled) সংরক্ষিত থাকে, হিসাব মেলাতে কাজে লাগবে।

### সীমাবদ্ধতা

- শুধু bKash — Nagad যোগ করতে চাইলে `middleware/bkash.js`-এর প্যাটার্ন অনুসরণ করে একটা `middleware/nagad.js` ও `routes/payments.js`-এ নতুন রুট যোগ করতে হবে (Nagad-এর API গঠন কিছুটা আলাদা, তাদের ডকুমেন্টেশন থেকে যাচাই করে নিন)
- রিফান্ড/ক্যান্সেলেশনের কোনো UI নেই — bKash-এর ড্যাশবোর্ড থেকে ম্যানুয়ালি করতে হবে, আর `purchases` টেবিল থেকে সংশ্লিষ্ট এন্ট্রি মুছে দিলে আবার লক হয়ে যাবে

## নতুন সংযোজন (ক্যাটাগরি, এডমিন ড্যাশবোর্ড, ভিউ-কাউন্ট, শেয়ারযোগ্য লিংক)

- **ক্যাটাগরি নেভিগেশন** — ইতিহাস / অর্থনীতি / শিক্ষাবিজ্ঞান, প্রতিটির নিচে নির্দিষ্ট সাব-ক্যাটাগরি ট্যাগ। তালিকা ঠিক করতে `middleware/categories.js` (সার্ভার) ও `public/categories.js` (ফ্রন্টএন্ড) — দুটোই একসাথে বদলাতে হবে, একই তালিকা ডুপ্লিকেট করা আছে বিল্ড-স্টেপ না থাকায়।
- **এডমিন ড্যাশবোর্ড** — লেখক প্রবেশ, নতুন লেখা, পেমেন্ট অনুরোধ — সব এখন `/admin`-এ, প্রধান নেভিগেশনে দেখা যায় না (মিনিমাল রাখতে)। ফুটারে একটা ছোট "লেখক" লিংক আছে।
- **শেয়ারযোগ্য লিংক** — প্রতিটা লেখার URL `/post/<id>`, "লিংক কপি করুন" বাটন দিয়ে কপি করা যায়।
- **ভিউ-কাউন্ট** — প্রতিদিন এক পাঠক = এক ভিউ (রিফ্রেশে বাড়ে না), লেখক ড্যাশবোর্ডে মোট/আজকের ভিউ দেখা যায়, প্রতিটা লেখায় "পরিসংখ্যান" বাটনে গত ১৪ দিন ও ৬ মাসের ব্রেকডাউন।
- **আমার কেনা লেখা ও ব্রাউজার-রিস্টোর** — `/purchases`-এ কেনা লেখার তালিকা; bKash নম্বর দিয়ে অন্য ব্রাউজার/ডিভাইসে আগের কেনাকাটা ফিরিয়ে আনা যায় (রেট-লিমিটেড)।

পুরনো (ক্যাটাগরিহীন) লেখাগুলো "সব লেখা" হোম ভিউতে (লোগোতে ক্লিক করলে) ঠিকই দেখা যাবে, শুধু কোনো নির্দিষ্ট ক্যাটাগরিতে ফিল্টার করলে দেখা যাবে না।

## সাবস্ক্রিপশন, লেখা জমা, প্রোফাইল

- **সাবস্ক্রিপশন** — মাসিক ৳১০০ / ষান্মাসিক ৳৫০০, সব পেইড লেখা একসাথে আনলক করে (প্রতি লেখা আলাদা কেনার বদলে)। প্ল্যান বদলাতে `middleware/plans.js` ও `public/plans.js` — দুটোই মিলিয়ে বদলান। রিনিউ করলে চলমান মেয়াদের শেষ থেকে নতুন মেয়াদ যোগ হয়।
- **লেখা জমা** — লগইন করা যে-কেউ "লিখুন" দিয়ে লেখা জমা দিতে পারেন। লেখক নিজে জমা দিলে সাথে সাথে প্রকাশ হয়ে যায়; অন্য কারও জমা লেখকের অনুমোদনের অপেক্ষায় থাকে (এডমিন ড্যাশবোর্ড → "লেখা জমা")।
- **প্রোফাইল** — লগইন করা প্রতিটি অ্যাকাউন্টের নিজস্ব পাতা, যেখানে ফোন নম্বর, সাবস্ক্রিপশনের অবস্থা, এবং আলাদাভাবে কেনা লেখার তালিকা একসাথে দেখা যায়।

পে-পার-পোস্ট (প্রতি লেখা আলাদা কেনা) আগের মতোই চালু আছে — সাবস্ক্রিপশনবিহীন পাঠকরা এখনও একটামাত্র লেখা কিনে পড়তে পারবেন।
